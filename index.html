small diffs.
deep causes.

most of my recent work starts with a deceptively simple question: why did two equivalent builds produce different artifacts?

case 01

making rust toolchain builds less path-dependent

tracked absolute build paths through crate metadata and native c/c++ debug info, then added targeted remapping at the points where those paths escaped existing coverage.

out_dir→metadata→debug info→artifact hash
  • remapped bootstrap out_dir into a stable virtual prefix.
  • forwarded debug-prefix remapping into native c/c++ builds used by rustc_llvm.
  • handled windows-style path forms and cc compiler detection gaps.

strengthened run-make coverage around reproducible builds instead of relying on narrower historical assumptions.

04 / about

“i like finding out why software behaves the way it does.”

i’m most at home around compilers, toolchains, binary formats, assembly, and the infrastructure that turns source into artifacts people can trust.

rust is my primary language, but the interesting bugs rarely respect language boundaries: they cross into c/c++, linker behavior, debug formats, build systems, filesystem paths, and ci.

i also write about what i’m learning — especially when building something from scratch is the clearest way to understand it.
